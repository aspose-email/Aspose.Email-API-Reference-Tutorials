## Implementatie‑gids

### Hoe parse ics file java: meerdere agenda‑gebeurtenissen lezen uit een ics‑bestand

#### Direct antwoord
Load het `.ics`‑bestand met `new CalendarReader("path/to/file.ics")`, en loop vervolgens `while (reader.nextEvent())` om elk `Appointment`‑object op te halen. Deze streaming‑aanpak leest evenementen één voor één, zodat zelfs grote agenda’s geheugen‑efficiënt blijven.

#### Overzicht
De `CalendarReader`‑klasse streamt evenementen uit een iCalendar‑bestand, waardoor je elke invoer één voor één kunt verwerken. Deze aanpak werkt goed zelfs bij grote bestanden omdat het voorkomt dat de volledige agenda in het geheugen wordt geladen.

**Definition anchor:** De `CalendarReader`‑klasse streamt VEVENT‑componenten uit een iCalendar‑bestand één voor één.  

#### Stapsgewijze gids

**1. Definieer het pad naar je .ics‑bestand**  
Vervang de placeholder door de daadwerkelijke locatie van je agenda‑bestand.

```java
String icsFilePath = "YOUR_DOCUMENT_DIRECTORY/US-Holidays.ics";
```

**2. Maak een `CalendarReader`‑instantie**  
De reader zal de laag‑niveau parsing voor je afhandelen.

```java
import com.aspose.email.CalendarReader;
import com.aspose.email.Appointment;

CalendarReader reader = new CalendarReader(icsFilePath);
```

**3. Itereer door elk evenement**  
Verzamel elk `Appointment`‑object in een lijst voor later gebruik.

**Definition anchor:** De `Appointment`‑klasse vertegenwoordigt een enkel agenda‑evenement met eigenschappen zoals starttijd, eindtijd, onderwerp en deelnemers.  

```java
List<Appointment> appointments = new ArrayList<>();
while (reader.nextEvent()) {
    appointments.add(reader.getCurrent());
}
```

#### Uitleg van de code
- `icsFilePath` – wijst naar het bron‑.ics‑bestand.  
- `CalendarReader reader` – opent het bestand en maakt het klaar voor sequentieel lezen.  
- `while (reader.nextEvent())` – brengt de reader naar het volgende evenement; de lus stopt wanneer er geen evenementen meer zijn.  
- `appointments` – een `List<Appointment>` die elk geparseerd evenement opslaat, klaar voor verdere verwerking (bijv. opslaan in een database of weergeven in een UI).

### Veelvoorkomende valkuilen & hoe ze te vermijden

- **Grote bestanden** – bij zeer grote agenda’s, overweeg om evenementen in batches te verwerken of direct naar een database te streamen om het geheugenverbruik laag te houden.
